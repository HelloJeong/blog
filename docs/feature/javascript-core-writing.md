# javascript-core 글 작성 컨벤션

`javascript-core/` 카테고리 하위 `.md` 블로그 글을 **작성·편집·리뷰**할 때 따라야 하는 상세 규칙입니다. `javascript-core/CLAUDE.md`의 요약 체크리스트를 풀어 쓴 문서입니다.

## 문서 헤더

모든 글은 아래 헤더로 시작합니다.

```markdown
# 번호. 제목

> _Javascript Core — AI를 잘 다루려면 내가 잘 알아야한다_

> [참고코드](./examples/{폴더명}/index.js)

---
```

- 제목은 `# 01. JavaScript 엔진과 런타임 환경` 형식 (번호 + 마침표 + 토픽명)
- 시리즈 인용구는 이탤릭으로 통일
- 참고코드 링크는 `./examples/{폴더명}/index.js` 경로 사용 (글과 예제가 같은 카테고리 폴더에 있으므로 상대 경로가 `./`로 시작)
- 예제가 여러 파일이면 폴더 링크로 변경

## 언어와 톤

- 본문은 한국어 존댓말 (~합니다, ~됩니다)
- 코드 주석은 반말 (`// 값을 반환한다`)
- 영문 기술 용어는 원어 그대로, 처음 등장 시 한국어 병기 (예: "AST(Abstract Syntax Tree, 추상 구문 트리)")
- 약어는 제목에서 `JIT(Just-In-Time)` 형태로 풀어서 표기

## 섹션 구조

소제목이 이미 작성되어 있으면 그 구조를 우선합니다.

### 섹션 기본 흐름

각 `##` 섹션은 다음 순서로 구성합니다.

1. **개념 정의** — 첫 1~2문장으로 무엇인지 설명
2. **시각적 보조자료** — 표, 텍스트 다이어그램, 코드 블록 중 1개 이상
3. **상세 설명** — 동작 원리, 단계별 분해, 실무 맥락
4. **섹션 끝 구분선** — `---`

### 섹션 제목 스타일

제목은 주제에 맞는 자연스러운 형태를 사용합니다.

- 질문형: `## JavaScript 엔진이란?`
- 흐름형: `## V8 엔진의 동작 흐름 (파싱 → AST → 바이트코드 → 최적화)`
- 비교형: `## 런타임 환경: 브라우저 vs Node.js`
- 주장형: `## Web API / libuv는 엔진의 일부가 아니다`

### 단계별 설명

흐름/과정을 설명할 때는 먼저 전체 다이어그램을 보여주고, 번호를 매겨 각 단계를 설명합니다.

```markdown
**1. 파싱**

설명 텍스트...

**2. Ignition — 바이트코드 생성**

설명 텍스트...
```

## 시각적 보조자료

### 텍스트 다이어그램

구조나 흐름은 일반 코드 블록(` ``` `)으로 표현합니다.

```
소스 코드
   ↓ 파싱 (Parser)
AST (Abstract Syntax Tree)
   ↓ Ignition (인터프리터)
바이트코드
```

트리 구조에는 `└──`, `├──` 문자를 사용합니다.

### 비교 테이블

관련 항목을 비교할 때 마크다운 테이블을 사용합니다.

```markdown
| 엔진 | 사용처          |
| ---- | --------------- |
| V8   | Chrome, Node.js |
```

### 코드 예제 규칙

- 언어 태그 필수: ` ```javascript ` 또는 ` ```typescript `
- ❌/✅ 이모지로 나쁜/좋은 예시 대비

```javascript
// ❌ 타입이 섞이면 최적화가 깨진다
add(1, 2);
add("a", "b");

// ✅ 타입을 일관되게 유지하면 최적화가 유지된다
add(1, 2);
add(3, 4);
```

- 코드 블록은 30줄 이내
- 실행 결과는 `// 출력: 1 → 3 → 2` 형태로 주석 표기

## 강조 및 인용 패턴

### 키워드 강조

핵심 용어는 **굵은 글씨**로 강조합니다.

- `**런타임 환경**이 제공합니다`
- `**JIT 컴파일**은 자주 실행되는 코드를 런타임에 최적화한다`

인라인 코드는 코드/API명에 사용합니다.

- `` `setTimeout`, `fetch`, `fs.readFile` ``

### 인용구 (`>`)

팁, 참고 정보, 면접 질문에 사용합니다.

```markdown
> AST를 직접 확인하고 싶다면 [astexplorer.net](https://astexplorer.net)에서 볼 수 있습니다.

> TypeScript를 쓰는 이유 중 하나가 여기에 있습니다.

> "setTimeout은 어디서 실행되나요?"
```

면접 관련 내용은 `면접에서 자주 나오는 질문입니다.` 같은 리드 문장을 앞에 둡니다.

## 정리 섹션

마지막 섹션은 `## 정리`로 통일합니다.

```markdown
## 정리

- **JS 엔진**은 코드를 파싱 → 바이트코드 → 기계어로 변환해 실행한다
- **키워드** 설명 (부가정보)
- 3~5개 불릿 포인트
```

- 각 항목에 **굵은 키워드** 포함
- 괄호로 부가 설명 추가 가능
- 존댓말이 아닌 간결한 서술체 (~한다, ~된다)
